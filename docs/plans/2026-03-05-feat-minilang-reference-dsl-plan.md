# MiniLang Reference DSL Implementation Plan

## Overview

Implement **MiniLang**, a reference Domain-Specific Language that demonstrates how to integrate custom DSLs with the JCP (Java Compiler Platform) middleware. MiniLang serves three purposes:

1. **End-user documentation by example** - Shows DSL authors how to build on JCP
2. **Onboarding guide** - Step-by-step template for creating custom DSLs
3. **Test bed** - Exercises all JCP capabilities including debugger integration

MiniLang will showcase ALL JCP features:
- Primitives (int, double, boolean, string)
- Variables with explicit type declarations
- Arithmetic, comparison, and logical operators
- Control flow (if/else, while, break, continue, return)
- User-defined functions with overloading and recursion
- Custom structs with fields and methods
- Arrays with literal syntax
- Module integration (Java interop via Logger)
- Both interpreter AND compiler execution modes

### Syntax Philosophy

**Minimalist Python/Ruby-inspired syntax** that's clean, readable, and educational:
- **Explicit types** - always annotate variable and function types for learning clarity
- **Newline-terminated** - no semicolons required
- **Braces for blocks** - clear structure without indentation complexity
- **Minimal keywords** - `let`, `func`, `struct`, `if`, `while`, `return`, `break`, `continue`
- **Clean function syntax** - `func name(params) -> type { body }`

Example program:
```minilang
# Variables with all primitive types
let count: int = 0
let pi: double = 3.14159
let greeting: string = "Hello, MiniLang!\n"
let active: boolean = true

# Custom struct with methods
struct Calculator {
    result: double,

    func add(value: double) -> void {
        this.result = this.result + value
    }

    func getResult() -> double {
        return this.result
    }
}

# Recursive function
func factorial(n: int) -> int {
    if n <= 1 {
        return 1
    }
    return n * factorial(n - 1)
}

# Main program
func main() -> void {
    print("=== MiniLang Demo ===\n")

    let calc: Calculator = Calculator(0.0)
    calc.add(10.5)
    calc.add(5.3)
    print(calc.getResult())  # 15.8

    print(factorial(5))  # 120
}

main()
```

## Problem Statement

JCP provides AST representation, type system, and dual-mode execution (interpreter + compiler), but **lacks concrete examples** showing DSL authors how to integrate their parsers. Current documentation in README shows code snippets but no complete, runnable DSL implementation.

**Pain Points for DSL Authors:**
1. No reference grammar showing ANTLR integration patterns
2. Unclear how to map parse trees to JCP AST nodes
3. No guidance on module system integration
4. Testing strategy for dual-mode execution not demonstrated
5. Source location attachment patterns scattered across docs

**Impact:**
- High barrier to entry for new DSL authors
- Repetitive questions about "how do I start?"
- Risk of anti-patterns without concrete examples

## Proposed Solution

Create a **complete reference DSL implementation** in a new Maven module `module/minilang/` that includes:

1. **ANTLR4 grammar** (`MiniLang.g4`) with all language constructs
2. **AST builder** (`AstBuilder.java`) converting parse trees to JCP AST nodes
3. **Runner** (`MiniLangRunner.java`) demonstrating both eval and compile modes
4. **Example programs** (`.minilang` files) showcasing each feature
5. **Integration tests** verifying dual-mode execution parity
6. **Comprehensive README** with "how to customize for your DSL" guide

### 2. ANTLR Grammar Design

**File:** `src/main/antlr4/com/elminster/minilang/MiniLang.g4`

**Key Grammar Rules:**

```antlr
grammar MiniLang;

// Entry point
program
    : statement* EOF
    ;

// Statement types
statement
    : variableDeclaration       # VarDeclStmt
    | functionDeclaration       # FuncDeclStmt
    | structDeclaration         # StructDeclStmt
    | ifStatement               # IfStmt
    | whileStatement            # WhileStmt
    | returnStatement           # ReturnStmt
    | breakStatement            # BreakStmt
    | continueStatement         # ContinueStmt
    | expressionStatement       # ExprStmt
    ;

// Variable declaration: let x: int = 10
variableDeclaration
    : 'let' ID ':' type '=' expression
    ;

// Function declaration: func add(a: int, b: int) -> int { return a + b }
functionDeclaration
    : 'func' ID '(' parameterList? ')' '->' type block
    ;

// Struct declaration: struct Point { x: int, y: int }
structDeclaration
    : 'struct' ID '{' fieldList? '}'
    ;

// Expressions with precedence
expression
    : expression '(' argumentList? ')'                          # FunctionCall
    | expression '.' ID                                         # FieldAccess
    | expression '[' expression ']'                             # ArrayAccess
    | expression '.' ID '(' argumentList? ')'                   # MethodCall
    | ('!' | '-') expression                                    # UnaryOp
    | expression ('*' | '/' | '%') expression                  # MultDiv
    | expression ('+' | '-') expression                        # AddSub
    | expression ('<' | '>' | '<=' | '>=') expression          # Comparison
    | expression ('==' | '!=') expression                      # Equality
    | expression '&&' expression                                # LogicalAnd
    | expression '||' expression                                # LogicalOr
    | literal                                                   # LiteralExpr
    | ID                                                        # Identifier
    | '(' expression ')'                                        # Parens
    | arrayLiteral                                              # ArrayLiteralExpr
    | structInstantiation                                       # StructInstExpr
    ;

// Type specifications
type
    : 'int' | 'double' | 'boolean' | 'string' | 'void'
    | ID                    # CustomType (struct names)
    | type '[' ']'          # ArrayType
    ;

// Literals
literal
    : INTEGER               # IntLiteral
    | DOUBLE                # DoubleLiteral
    | STRING                # StringLiteral
    | BOOLEAN               # BoolLiteral
    ;

arrayLiteral
    : '[' (expression (',' expression)*)? ']'
    ;

structInstantiation
    : ID '(' argumentList? ')'
    ;

// Helper rules
parameterList
    : parameter (',' parameter)*
    ;

parameter
    : ID ':' type
    ;

fieldList
    : fieldDeclaration (',' fieldDeclaration)*
    ;

fieldDeclaration
    : ID ':' type
    | functionDeclaration  # StructMethod
    ;

argumentList
    : expression (',' expression)*
    ;

block
    : '{' statement* '}'
    ;

// Lexer rules
ID          : [a-zA-Z_][a-zA-Z0-9_]* ;
INTEGER     : [0-9]+ ;
DOUBLE      : [0-9]+ '.' [0-9]+ ;
STRING      : '"' (~["\r\n] | '\\' .)* '"' ;
BOOLEAN     : 'true' | 'false' ;
COMMENT     : '#' ~[\r\n]* -> skip ;
WS          : [ \t\r\n]+ -> skip ;
```

**Grammar Features:**
- Left-recursive expression rules for proper precedence
- Visitor pattern enabled (`-visitor` flag)
- Standard C/Java operator precedence
- Newline-insensitive (WS handles all whitespace)
- String escapes handled in lexer

### 3. AST Builder Implementation

**File:** `src/main/java/com/elminster/minilang/AstBuilder.java`

**Core Responsibilities:**
1. Convert ANTLR parse tree to JCP AST nodes
2. Attach source locations to every node
3. Resolve type names using context
4. Handle string escape sequences
5. Map operators to JCP expression nodes

**Key Visitor Methods:**

```java
public class AstBuilder extends MiniLangBaseVisitor<AstNode> {
    private final String sourceFile;
    private final String[] sourceLines;
    private final TypeResolver typeResolver;

    public AstBuilder(String sourceFile, String source) {
        this.sourceFile = sourceFile;
        this.sourceLines = source.split("\n");
        this.typeResolver = new TypeResolver();
    }

    @Override
    public AstNode visitProgram(MiniLangParser.ProgramContext ctx) {
        Block program = new BlockImpl();
        for (MiniLangParser.StatementContext stmt : ctx.statement()) {
            program.addStatement((Statement) visit(stmt));
        }
        return program;
    }

    @Override
    public AstNode visitVarDeclStmt(MiniLangParser.VarDeclStmtContext ctx) {
        String name = ctx.variableDeclaration().ID().getText();
        DataType type = typeResolver.resolve(ctx.variableDeclaration().type());
        Expression init = (Expression) visit(ctx.variableDeclaration().expression());

        VariableDeclarationImpl decl = new VariableDeclarationImpl(name, type, init);
        decl.setLocation(locationFrom(ctx));
        return decl;
    }

    @Override
    public AstNode visitFuncDeclStmt(MiniLangParser.FuncDeclStmtContext ctx) {
        MiniLangParser.FunctionDeclarationContext funcCtx = ctx.functionDeclaration();
        String name = funcCtx.ID().getText();
        ParameterDef[] params = parseParameters(funcCtx.parameterList());
        DataType returnType = typeResolver.resolve(funcCtx.type());
        Block body = (Block) visit(funcCtx.block());

        AbstractFunction func = new AbstractFunction(
            IdentifierExpression.of(name),
            params,
            returnType,
            body
        );
        func.setLocation(locationFrom(ctx));
        return new FunctionDeclarationImpl(func);
    }

    @Override
    public AstNode visitStructDeclStmt(MiniLangParser.StructDeclStmtContext ctx) {
        MiniLangParser.StructDeclarationContext structCtx = ctx.structDeclaration();
        String name = structCtx.ID().getText();
        List<StructFieldDef> fields = parseFields(structCtx.fieldList());

        StructDeclarationImpl structDecl = new StructDeclarationImpl(name, fields);
        structDecl.setLocation(locationFrom(ctx));
        return structDecl;
    }

    @Override
    public AstNode visitAddSub(MiniLangParser.AddSubContext ctx) {
        Expression left = (Expression) visit(ctx.expression(0));
        Expression right = (Expression) visit(ctx.expression(1));

        Expression expr;
        if (ctx.op.getText().equals("+")) {
            expr = new Plus(left, right);
        } else {
            expr = new Minus(left, right);
        }
        expr.setLocation(locationFrom(ctx));
        return expr;
    }

    @Override
    public AstNode visitArrayLiteralExpr(MiniLangParser.ArrayLiteralExprContext ctx) {
        MiniLangParser.ArrayLiteralContext arrCtx = ctx.arrayLiteral();
        List<Expression> elements = new ArrayList<>();

        for (MiniLangParser.ExpressionContext exprCtx : arrCtx.expression()) {
            elements.add((Expression) visit(exprCtx));
        }

        ArrayLiteralExpression arrayLiteral = new ArrayLiteralExpression(
            elements.toArray(new Expression[0])
        );
        arrayLiteral.setLocation(locationFrom(ctx));
        return arrayLiteral;
    }

    // Helper: Extract source location from ANTLR context
    private SourceLocation locationFrom(ParserRuleContext ctx) {
        Token start = ctx.getStart();
        Token stop = ctx.getStop();
        int line = start.getLine();
        String sourceLine = (line > 0 && line <= sourceLines.length)
            ? sourceLines[line - 1] : null;

        // ANTLR uses 0-based columns, convert to 1-based
        return SourceLocation.span(
            sourceFile,
            line, start.getCharPositionInLine() + 1,
            stop.getLine(), stop.getCharPositionInLine() + stop.getText().length(),
            sourceLine
        );
    }

    // Helper: Parse string with escape sequences
    private String parseStringLiteral(String raw) {
        // Remove quotes
        String content = raw.substring(1, raw.length() - 1);

        // Process escapes: \n, \t, \", \\
        return content
            .replace("\\n", "\n")
            .replace("\\t", "\t")
            .replace("\\\"", "\"")
            .replace("\\\\", "\\");
    }

    // ... additional visitor methods for all grammar rules
}
```

**TypeResolver Helper:**

```java
public class TypeResolver {
    public DataType resolve(MiniLangParser.TypeContext ctx) {
        String typeName = ctx.getText();

        // Check for array types: int[]
        if (typeName.endsWith("[]")) {
            String baseTypeName = typeName.substring(0, typeName.length() - 2);
            SystemDataType baseType = resolveSystemType(baseTypeName);
            return baseType != null ? baseType.getArrayType() : SystemDataType.ANY;
        }

        // Check system types
        SystemDataType systemType = resolveSystemType(typeName);
        if (systemType != null) {
            return systemType;
        }

        // Custom type (struct name)
        return new DataTypeImpl(typeName);
    }

    private SystemDataType resolveSystemType(String name) {
        return switch (name.toLowerCase()) {
            case "int" -> SystemDataType.INT;
            case "double" -> SystemDataType.DOUBLE;
            case "boolean" -> SystemDataType.BOOLEAN;
            case "string" -> SystemDataType.STRING;
            case "void" -> SystemDataType.VOID;
            default -> null;
        };
    }
}
```

### 4. Runner Implementation

**File:** `src/main/java/com/elminster/minilang/MiniLangRunner.java`

```java
public class MiniLangRunner {
    public static void main(String[] args) throws Exception {
        if (args.length < 2) {
            System.err.println("Usage: java MiniLangRunner <mode> <file.minilang>");
            System.err.println("  mode: eval | compile");
            System.exit(1);
        }

        String mode = args[0];
        String sourceFile = args[1];
        String source = Files.readString(Path.of(sourceFile));

        // Parse with ANTLR
        CharStream input = CharStreams.fromString(source);
        MiniLangLexer lexer = new MiniLangLexer(input);
        CommonTokenStream tokens = new CommonTokenStream(lexer);
        MiniLangParser parser = new MiniLangParser(tokens);

        // Error handling
        parser.removeErrorListeners();
        parser.addErrorListener(new BaseErrorListener() {
            @Override
            public void syntaxError(Recognizer<?, ?> recognizer, Object offendingSymbol,
                                    int line, int charPositionInLine, String msg,
                                    RecognitionException e) {
                System.err.printf("Syntax error at %d:%d - %s%n",
                    line, charPositionInLine, msg);
            }
        });

        MiniLangParser.ProgramContext parseTree = parser.program();

        // Build JCP AST
        AstBuilder builder = new AstBuilder(sourceFile, source);
        Block program = (Block) builder.visit(parseTree);

        // Execute based on mode
        if ("eval".equals(mode)) {
            executeEvalMode(program);
        } else if ("compile".equals(mode)) {
            executeCompileMode(program, sourceFile);
        } else {
            System.err.println("Unknown mode: " + mode);
            System.exit(1);
        }
    }

    private static void executeEvalMode(Block program) {
        RootEvalContext context = new RootEvalContext();
        new EvalVisitor(context).visit(program);
    }

    private static void executeCompileMode(Block program, String sourceFile)
            throws Exception {
        JcpCompiler compiler = new JcpCompiler();

        // Generate unique class name from source file
        String className = "MiniLang_" +
            Path.of(sourceFile).getFileName().toString().replace(".", "_");

        Class<?> clazz = compiler.compileAndLoad(program, className);
        Method mainMethod = clazz.getMethod("main", String[].class);
        mainMethod.invoke(null, (Object) new String[]{});
    }
}
```

// MUST follow standard type resolution order
private DataType resolveDataType(String typeName, CompileContext ctx) {
    // 1. Check system types (INT, DOUBLE, etc.)
    for (SystemDataType sdt : SystemDataType.values()) {
        if (sdt.getName().equalsIgnoreCase(typeName)) {
            return sdt;
        }
    }

    // 2. Check custom types (struct names)
    DataType customType = ctx.getDataType(typeName);
    if (customType != null) {
        return customType;
    }

    // 3. Fallback
    return SystemDataType.ANY;
}

```java
@Test
void testFunctionsInBothModes() throws Exception {
    String source = Files.readString(
        Path.of("src/main/resources/examples/04-functions.minilang")
    );

    // Parse
    Block program = parseProgram(source);

    // Execute in eval mode
    RootEvalContext evalContext = new RootEvalContext();
    ByteArrayOutputStream evalOutput = captureOutput(() -> {
        new EvalVisitor(evalContext).visit(program);
    });

    // Execute in compile mode
    ByteArrayOutputStream compileOutput = captureOutput(() -> {
        JcpCompiler compiler = new JcpCompiler();
        Class<?> clazz = compiler.compileAndLoad(program, "TestFunctions");
        clazz.getMethod("main", String[].class).invoke(null, (Object) new String[]{});
    });

    // Verify identical output
    assertEquals(evalOutput.toString(), compileOutput.toString());
}
```

**Critical Testing Gotcha (from solutions):**
When testing custom types (structs), MUST use `compileToMultipleClasses()` and `MultiClassLoader`:

```java
@Test
void testStructsWithMultiClassLoader() throws Exception {
    Block program = buildStructProgram();

    JcpCompiler compiler = new JcpCompiler();
    Map<String, byte[]> allClasses = compiler.compileToMultipleClasses(
        program, "TestStructs"
    );

    // Load all classes (main class + struct classes)
    MultiClassLoader loader = new MultiClassLoader();
    for (Map.Entry<String, byte[]> entry : allClasses.entrySet()) {
        loader.defineClass(entry.getKey(), entry.getValue());
    }

    Class<?> clazz = loader.loadClass("TestStructs");
    Method mainMethod = clazz.getMethod("main", String[].class);
    mainMethod.invoke(null, (Object) new String[]{});
}
```

## Alternative Approaches Considered

### Alternative 1: Inline DSL in Core Module
**Approach:** Add MiniLang directly to `core/src/test/java/` as test utilities

**Pros:**
- No new Maven module needed
- Faster to implement
- Immediate use in tests

**Cons:**
- Mixes test infrastructure with production code
- Harder to discover as a reference example
- No clear separation for documentation
- Violates single responsibility principle

**Rejected because:** Separate module provides cleaner architecture and better discoverability for DSL authors.

---

### Alternative 2: External Repository
**Approach:** Create standalone `jcp-minilang` repository

**Pros:**
- Complete independence
- Own versioning and release cycle
- Can showcase integration from external perspective

**Cons:**
- Harder to maintain sync with JCP core
- Duplication of build configuration
- Users must find and clone separately
- Increases barrier to entry

**Rejected because:** Keeping MiniLang in-tree ensures it stays current with JCP APIs and is immediately discoverable.

---

### Alternative 3: No ANTLR - Manual Parser
**Approach:** Implement hand-written recursive descent parser

**Pros:**
- No external dependencies
- Full control over error messages
- Potentially simpler for minimal DSL

**Cons:**
- Misses the point - users will use parser generators
- More code to maintain
- Doesn't demonstrate real-world integration pattern
- Less educational for DSL authors

**Rejected because:** ANTLR is industry-standard for DSL development. Reference implementation should show best practices.

---

### Alternative 4: Multiple Mini-DSLs
**Approach:** Create several tiny DSLs (Calculator, Simple Scripting, etc.)

**Pros:**
- Shows variation in approaches
- Each example simpler
- Multiple templates to choose from

**Cons:**
- Fragmented documentation
- Harder to showcase all JCP features
- More maintenance burden
- Risk of overwhelming users with choices

**Rejected because:** Single comprehensive example better demonstrates complete integration while remaining focused.

## Risk Analysis & Mitigation

### Technical Risks

**Risk 1: ANTLR Grammar Conflicts**
- **Severity:** Medium
- **Likelihood:** Medium
- **Impact:** Delays Phase 1, potential redesign of grammar rules
- **Mitigation:**
  - Start with simple grammar, add complexity incrementally
  - Use ANTLR's conflict resolution tools
  - Reference existing grammar examples (Java, Python)
  - Test grammar with edge cases early
- **Contingency:** Simplify syntax if conflicts persist (e.g., require parentheses)

**Risk 2: Eval/Compile Mode Parity Issues**
- **Severity:** High
- **Likelihood:** Medium
- **Impact:** Broken contract, incorrect results in one mode
- **Mitigation:**
  - Dual-mode tests from day one
  - Follow eval mode implementation when writing compile mode
  - Capture and compare output streams
  - Check solutions docs for documented gotchas
- **Contingency:** Add explicit parity checks in integration tests

**Risk 3: Custom Type Registration Failures**
- **Severity:** High
- **Likelihood:** Low (well-documented in solutions)
- **Impact:** `NoClassDefFoundError` at runtime, struct methods fail
- **Mitigation:**
  - Follow dual-registration pattern: `addDataType()` + `addGeneratedClass()`
  - Test all compilation entry points
  - Check `StructCompileTest.java` for reference
  - Use `MultiClassLoader` for struct tests
- **Contingency:** Add explicit registration verification in tests

**Risk 4: Test Coverage < 80%**
- **Severity:** High
- **Likelihood:** Low
- **Impact:** Build fails on `mvn verify`, blocks merge
- **Mitigation:**
  - Write tests in parallel with implementation
  - Run JaCoCo after each phase
  - Focus on branch coverage (harder than instruction)
  - Add edge case tests
- **Contingency:** Reduce scope (fewer example features) to maintain coverage

### Documentation Risks
