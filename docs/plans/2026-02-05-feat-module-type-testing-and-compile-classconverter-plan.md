# Module Type Testing and Compile-Mode ClassConverter

## Overview

Add comprehensive tests for built-in module types (Logger, Assertions, ValueBuffer) in both eval and compile modes, and implement a compile-mode ClassConverter that enables JCP bytecode to call methods on external Java classes (including 3rd-party JARs).

## Problem Statement / Motivation

Currently:
1. **Eval mode** has full support for module types via `ClassConverter.registerClass()` but lacks comprehensive tests
2. **Compile mode** has NO support for external Java classes - only user-defined `StructType` works
3. Users cannot call methods on external JAR classes from compiled JCP code
4. No way to verify eval/compile mode parity for module types

This blocks:
- Using standard Java libraries (Apache Commons, Guava, etc.) in JCP
- Interoperability between JCP and existing Java codebases
- Validating that module types work identically in both modes

## Proposed Solution

### Phase 1: Test Infrastructure for Module Types

Create comprehensive tests for Logger, Assertions, and ValueBuffer that:
- Verify eval mode functionality works correctly
- Prepare for compile mode testing once ClassConverter is implemented
- Ensure parity between eval and compile modes

### Phase 2: Compile-Mode ExternalClassType

Create a new type (`ExternalClassType`) that represents Java classes in the compile-time type system:
- Stores method signatures extracted via reflection
- Compatible with existing type resolution
- Can be used by method call compilers

### Phase 3: Compile-Mode ClassConverter

Create `CompileModeClassConverter` that:
- Analyzes Java classes via reflection at registration time
- Creates `ExternalClassType` with method metadata
- Registers types in `CompileContext` for compile-time lookup
- Generates correct bytecode for external class method calls

### Phase 4: Integration and 3rd-Party JAR Support

- Link generated bytecode with external classes in unified ClassLoader
- Enable users to register arbitrary JAR classes
- Test with common libraries (Apache Commons StringUtils, etc.)

## Technical Approach

### Architecture Decision: Utility Class Pattern

`CompileModeClassConverter` will be a **utility class** (not a compiler) that:
1. Is called during compilation initialization (like `RootEvalContext.registerSystemFunctions()`)
2. Registers `ExternalClassType` instances in `CompileContext`
3. Existing `StaticMethodCallCompiler` and `MethodCallCompiler` extended to handle `ExternalClassType`

This follows the existing eval-mode pattern and minimizes changes to compiler infrastructure.

### Modified Classes

#### StaticMethodCallCompiler.java

```java
// Extend to handle ExternalClassType
@Override
public void compile(MethodVisitor mv, CompileContext ctx) {
    DataType dataType = ctx.getDataType(typeName);

    if (dataType instanceof StructType) {
        // Existing struct method call logic
    } else if (dataType instanceof ExternalClassType) {
        // NEW: External class method call
        ExternalClassType extType = (ExternalClassType) dataType;
        ExternalMethodDef method = extType.getStaticMethod(methodName, argTypes);

        // Compile arguments
        compileArguments(mv, args, method.getParameterTypes());

        // Emit INVOKESTATIC with external class name
        mv.visitMethodInsn(
            Opcodes.INVOKESTATIC,
            Type.getInternalName(extType.getJavaClass()),  // e.g., "com/elminster/jcp/module/base/logger/Logger"
            methodName,
            method.getDescriptor(),
            false
        );
    }
}
```

#### MethodCallCompiler.java

```java
// Extend to handle ExternalClassType
@Override
public void compile(MethodVisitor mv, CompileContext ctx) {
    if (targetType instanceof StructType) {
        // Existing struct instance method call logic
    } else if (targetType instanceof ExternalClassType) {
        // NEW: External class instance method call
        ExternalClassType extType = (ExternalClassType) targetType;
        ExternalMethodDef method = extType.getInstanceMethod(methodName, argTypes);

        // Target object already on stack
        compileArguments(mv, args, method.getParameterTypes());

        // Emit INVOKEVIRTUAL with external class name
        mv.visitMethodInsn(
            Opcodes.INVOKEVIRTUAL,
            Type.getInternalName(extType.getJavaClass()),
            methodName,
            method.getDescriptor(),
            false
        );
    }
}
```

### Type Mapping: Java to JCP

| Java Type | JCP DataType |
|-----------|--------------|
| `int`, `Integer` | `SystemDataType.INT` |
| `double`, `Double` | `SystemDataType.DOUBLE` |
| `boolean`, `Boolean` | `SystemDataType.BOOLEAN` |
| `String` | `SystemDataType.STRING` |
| `void` | `SystemDataType.VOID` |
| `Object` | `SystemDataType.ANY` |
| Other classes | `ExternalClassType` |

1. Load generated JCP classes
