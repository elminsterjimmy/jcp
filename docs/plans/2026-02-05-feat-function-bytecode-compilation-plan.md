# Function Bytecode Compilation

## Enhancement Summary

**Deepened on:** 2026-02-05
**Sections enhanced:** 8
**Research agents used:** Architecture Strategist, Performance Oracle, Code Simplicity Reviewer, Pattern Recognition Specialist, Best Practices Researcher, Learnings Researcher (3 docs)

### Key Improvements from Research

1. **Context Management Fix**: Function context should use `parent = rootContext` with `setNextLocalIndex(0)` override, not fully isolated context - enables access to function registry and type registry while isolating local variables
2. **Function Registry Optimization**: Use composite key `Map<FunctionSignatureKey, FunctionSignature>` for O(1) exact-match lookups instead of O(n) linear scan
3. **Type Resolution Required**: All parameter and return types must use three-step resolution pattern (system → custom → fallback) to support struct types
4. **Directory Path Fix**: Use `compile/declare/` not `compile/declaration/` to match existing `StructDeclarationCompiler` location
5. **Simplification Option**: Consider single-pass without overloading for v1 (~145 LOC vs ~350 LOC)

### Critical Issues to Address

- **ReturnCompiler validation**: Add null check for return type and void/non-void validation
- **Generated class delegation**: If functions can contain struct declarations, funcCtx must delegate to rootContext
- **Main method return type**: Initialize `rootContext.setCurrentFunctionReturnType(SystemDataType.VOID)`

## Overview

Compile existing JCP function support (already working in eval mode) to JVM bytecode. This enables function declarations, function calls, recursion, and function overloading to execute as native JVM static methods.

## Problem Statement / Motivation

JCP has dual-mode execution: interpreter (`eval/`) and bytecode compiler (`compile/`). Currently, function support only works in eval mode. To complete the compiler feature parity, functions must be compiled to JVM bytecode.

**What already works in eval mode:**
- Function declaration with parameters and return type
- Function calls with arguments
- Recursion (Fibonacci test passes in `RecursionTest.java`)
- Function overloading (by parameter types)
- Return statements

**Goal:** Make all of this work in compile mode with identical behavior.

## Proposed Solution

Compile JCP functions as `public static` methods in the same generated class. Use two-pass compilation to support forward references (functions called before declaration).

### Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Method type | `public static` | Matches eval (no `this` context) |
| Class structure | Single class | All functions as methods alongside `main()` |
| Overloading | JVM descriptor matching | Simpler than name mangling; Java-native |
| Scope | Function-local only | Each function has isolated local variable table |
| Global access | Not supported | Functions access only params and locals |
| Forward refs | Two-pass compilation | Pass 1 registers signatures, Pass 2 generates bytecode |

### Bytecode Generation Strategy

**JCP Function:**
```java
func add(int a, int b) -> int { return a + b; }
```

**Generated Bytecode:**
```java
public static int add(int a, int b) {
    ILOAD 0      // load param a
    ILOAD 1      // load param b
    IADD
    IRETURN
}
```

**Function Call:**
```java
int result = add(1, 2);
```

**Generated Bytecode:**
```java
ICONST_1
ICONST_2
INVOKESTATIC ClassName.add(II)I
ISTORE <result_index>
```

### Research Insights: ASM Best Practices

**From ASM Documentation and Context7:**

1. **Always use COMPUTE_FRAMES** - Already in BytecodeGenerator (`ClassWriter.COMPUTE_FRAMES | ClassWriter.COMPUTE_MAXS`)
2. **visitCode() → instructions → visitMaxs() → visitEnd()** - Required sequence for valid bytecode
3. **Static methods start parameters at index 0** - No implicit `this` parameter
4. **Double/long use 2 slots** - TypeMapper.getSlotSize() handles this correctly
5. **Use CheckClassAdapter during development** - Validates bytecode before runtime

```java
// Validation pattern for debugging
ClassReader reader = new ClassReader(bytecode);

CheckClassAdapter.verify(reader, false, new PrintWriter(sw));
if (!sw.toString().isEmpty()) {
    throw new RuntimeException("Invalid bytecode: " + sw);
}
```

// TypeResolver.java (NEW utility class)
public static DataType resolveDataType(String typeName, CompileContext ctx) {
    // 1. Check system types (fast path for primitives)
    for (SystemDataType sdt : SystemDataType.values()) {
        if (sdt.getName().equalsIgnoreCase(typeName)) {
            return sdt;
        }
    }

    // 2. Check custom types (structs, functions)
    DataType customType = ctx.getDataType(typeName);
    if (customType != null) {
        return customType;

    return SystemDataType.ANY;
}

### Research Insights: Performance Optimization

**From Performance Oracle - Current Grade: B-**

**Issue:** Linear scan through all functions for overload resolution is O(n).

**Optimization:** Use composite key for O(1) exact-match lookup:

```java
// CompileContext.java - Optimized registry

public static class FunctionSignatureKey {
    private final String name;
    private final String descriptor;  // e.g., "(II)I"

    // equals/hashCode based on both fields
}

// Optimized storage:
private Map<FunctionSignatureKey, FunctionSignature> functionRegistry = new HashMap<>();
private Map<String, Set<FunctionSignature>> functionsByName = new HashMap<>();  // For error messages

// Optimized lookup:
public FunctionSignature lookupFunction(String name, DataType[] argTypes) {
    String descriptor = TypeMapper.buildMethodDescriptor(argTypes, null);
    FunctionSignatureKey key = new FunctionSignatureKey(name, descriptor);

    // O(1) exact match
    FunctionSignature exact = functionRegistry.get(key);
    if (exact != null) return exact;

    // Fallback: O(k) where k = overloads for this name
    Set<FunctionSignature> candidates = functionsByName.get(name);
    return findCompatibleSignature(candidates, argTypes);
}
```

**Performance Gain:** 100x faster for 500+ functions with overloading.

**Key pattern from learnings:** Use dual registration - `registerFunction()` for compile-time lookup, generated bytecode stored via existing `addGeneratedClass()` mechanism.

#### Phase 2: Declaration Compiler

**2a. BytecodeGenerator.java - Two-pass compilation**

Modify `compile()` method:

```java
// BytecodeGenerator.java

public byte[] compile(Block program, String className) {
    this.className = className;

    // Class header
    classWriter.visit(V1_8, ACC_PUBLIC | ACC_SUPER, className, null, "java/lang/Object", null);
    generateDefaultConstructor();

    // Pass 1: Register all function signatures
    rootContext = new CompileContext();
    rootContext.setClassName(className);
    for (Statement stmt : program.getBody().getStatements()) {
        if (stmt instanceof FunctionDeclaration) {
            FunctionDeclaration fd = (FunctionDeclaration) stmt;
            // CRITICAL: Resolve types before registering
            DataType resolvedReturnType = TypeResolver.resolveDataType(
                fd.getDataType().getName(), rootContext);
            rootContext.registerFunction(
                fd.getId().getId(),
                fd.getParameterDefines(),
                resolvedReturnType
            );
        }
    }

    // Pass 2a: Generate method for each function
    for (Statement stmt : program.getBody().getStatements()) {
        if (stmt instanceof FunctionDeclaration) {
            generateFunctionMethod((FunctionDeclaration) stmt);
        }
    }

    // Pass 2b: Generate main() with non-function statements
    generateMainMethod(program);

    classWriter.visitEnd();
    return classWriter.toByteArray();
}
```

**2b. FunctionDeclarationCompiler.java - New file**

```java
// compile/declare/FunctionDeclarationCompiler.java (NOTE: declare/ not declaration/)

public class FunctionDeclarationCompiler extends AbstractAstCompiler {

    @Override
    public void compile(MethodVisitor mv, CompileContext ctx) {
        // In two-pass mode, this is called during Pass 2a
        // The actual method generation happens in BytecodeGenerator.generateFunctionMethod()
        // This compiler only registers the function signature (for single-pass compatibility)

        FunctionDeclaration fd = (FunctionDeclaration) astNode;
        ctx.registerFunction(
            fd.getId().getId(),
            fd.getParameterDefines(),
            fd.getDataType()
        );
        // No bytecode emitted to main method's MethodVisitor
    }

    /**
     * Compile function body statements. Called by BytecodeGenerator.
     * Follows separation of concerns pattern - generator handles method setup,
     * compiler handles body logic.
     */
    public void compileBody(MethodVisitor mv, CompileContext funcCtx) {
        FunctionDeclaration fd = (FunctionDeclaration) astNode;

        // Allocate parameters with RESOLVED types
        for (ParameterDef param : fd.getParameterDefines()) {
            DataType resolvedType = TypeResolver.resolveDataType(
                param.getDataType().getName(), funcCtx);
            funcCtx.allocateLocal(param.getId(), resolvedType);
        }

        // Compile body statements via visitor pattern
        for (Statement stmt : fd.getBody().getStatements()) {
            Compilable compiler = AstCompilerFactory.getCompiler(stmt);
            compiler.compile(mv, funcCtx);
        }

        // Implicit return for void functions
        if (fd.getDataType() == SystemDataType.VOID) {
            mv.visitInsn(Opcodes.RETURN);
        }
    }
}
```

**2c. BytecodeGenerator.generateFunctionMethod() - New method**

```java
// BytecodeGenerator.java

private void generateFunctionMethod(FunctionDeclaration fd) {
    String methodName = fd.getId().getId();

    // CRITICAL: Resolve return type before building descriptor
    DataType resolvedReturnType = TypeResolver.resolveDataType(
        fd.getDataType().getName(), rootContext);

    String descriptor = TypeMapper.buildMethodDescriptor(
        fd.getParameterDefines(),
        resolvedReturnType
    );

    // Create method
    MethodVisitor mv = classWriter.visitMethod(
        ACC_PUBLIC | ACC_STATIC,
        methodName,
        descriptor,
        null,
        null
    );
    mv.visitCode();

    // CRITICAL: Use parent context with reset local index (not isolated)
    CompileContext funcCtx = new CompileContext(rootContext);  // Inherit registries
    funcCtx.setClassName(className);
    funcCtx.setNextLocalIndex(0);  // Reset for static method parameters
    funcCtx.setCurrentFunctionReturnType(resolvedReturnType);

    // CRITICAL: Delegate generated classes to rootContext (for nested structs)
    funcCtx.setGeneratedClassDelegate(rootContext);

    // Delegate body compilation to FunctionDeclarationCompiler
    FunctionDeclarationCompiler compiler = new FunctionDeclarationCompiler(fd);
    compiler.compileBody(mv, funcCtx);

    mv.visitMaxs(0, 0);  // Auto-computed with COMPUTE_FRAMES
    mv.visitEnd();
}
```

#### Phase 3: Call Compiler

**3a. FunCallCompiler.java - New file**

```java
// compile/function/FunCallCompiler.java

public class FunCallCompiler extends AbstractAstCompiler {

    @Override
    public void compile(MethodVisitor mv, CompileContext ctx) {
        FunctionCallExpression call = (FunctionCallExpression) astNode;
        String funcName = call.getId().getId();
        Expression[] args = call.getArguments();

        // Determine argument types for overload resolution
        DataType[] argTypes = new DataType[args.length];
        for (int i = 0; i < args.length; i++) {
            argTypes[i] = TypeMapper.getExpressionType(args[i], ctx);
        }

        // Lookup function signature
        FunctionSignature sig = ctx.lookupFunction(funcName, argTypes);
        if (sig == null) {
            throw new CompileException("Undefined function: " + funcName +
                " with argument types " + Arrays.toString(argTypes));
        }

        // Compile arguments (push values onto stack)
        for (int i = 0; i < args.length; i++) {
            Compilable argCompiler = AstCompilerFactory.getCompiler(args[i]);
            argCompiler.compile(mv, ctx);

            // Type promotion if needed (int to double)
            DataType argType = argTypes[i];
            DataType paramType = sig.getParameters()[i].getDataType();
            if (paramType == SystemDataType.DOUBLE && argType == SystemDataType.INT) {
                mv.visitInsn(Opcodes.I2D);
            }
        }

        // Emit INVOKESTATIC
        mv.visitMethodInsn(
            Opcodes.INVOKESTATIC,
            ctx.getClassName(),
            funcName,
            sig.getDescriptor(),
            false
        );
        // Result (if any) is now on stack
    }
}
```

**4a. ReturnCompiler.java - Fix return type handling**

```java
// compile/control/ReturnCompiler.java (MODIFY existing file)

@Override
public void compile(MethodVisitor mv, CompileContext ctx) {
    ReturnStatement returnStmt = (ReturnStatement) astNode;
    Expression returnExpr = returnStmt.getExpression();

    // Get declared return type from context
    DataType returnType = ctx.getCurrentFunctionReturnType();

    // CRITICAL: Validate return type is set (from Architecture review)
    if (returnType == null) {
        throw new CompileException("Return statement outside function context");
    }

    // CRITICAL: Validate void/non-void consistency
    if (returnType == SystemDataType.VOID && returnExpr != null) {
        throw new CompileException("Void function cannot return a value");
    }
    if (returnType != SystemDataType.VOID && returnExpr == null) {
        throw new CompileException("Non-void function must return a value");
    }

    if (returnExpr != null) {
        // Compile return expression
        AstCompilerFactory.getCompiler(returnExpr).compile(mv, ctx);

        // Emit correct return instruction
        int returnOpcode = TypeMapper.getReturnOpcode(returnType);
        mv.visitInsn(returnOpcode);
    } else {
        // Void return
        mv.visitInsn(Opcodes.RETURN);
    }
}
```

**Note:** TypeMapper.getReturnOpcode() already exists and returns IRETURN/DRETURN/ARETURN/RETURN based on type.

## Open Questions (Resolved)

**Q1: Class structure?**
A: All functions as static methods in same class as `main()`.

**Q2: Global variable access?**
A: Not supported. Functions can only access parameters and local variables.

**Q3: Signature identity for overloading?**
A: Name + parameter types (Java-style). Return type not part of signature.

**Q4: Missing return detection?**
A: Void functions get implicit `RETURN`. Non-void functions rely on AST having return statements (eval mode validates this).

**Q5: Closure support?**
A: Not supported. Accessing non-local variables will cause "undefined variable" compile error.

**Q6: Function context inheritance?** (NEW)
A: Use `parent = rootContext` with `setNextLocalIndex(0)` override. Inherits registries but isolates local variables.

**Q7: Struct types in function signatures?** (NEW)
A: Must use TypeResolver.resolveDataType() for all parameter and return types.
