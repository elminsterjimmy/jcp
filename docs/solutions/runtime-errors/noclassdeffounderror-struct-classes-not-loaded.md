# NoClassDefFoundError - Struct Classes Not Loaded in compileWithReturn

## Problem Summary

When using `BytecodeGenerator.compileWithReturn()` to compile JCP programs with struct types, tests failed with `NoClassDefFoundError: Point` at runtime. The struct classes were being generated but not loaded by `MultiClassLoader`, causing runtime failures when the generated bytecode tried to reference them.

## Symptoms

**Error Message:**
```
java.lang.NoClassDefFoundError: Point
    at TestMultipleStructVars_2.evaluate(Unknown Source)
    at com.elminster.jcp.compile.struct.StructCompileTest.testFieldAccess(StructCompileTest.java:153)

Caused by: java.lang.ClassNotFoundException: Point
    at java.lang.ClassLoader.findClass(ClassLoader.java:733)
    at com.elminster.jcp.compile.MultiClassLoader.findClass(MultiClassLoader.java:50)
```

**Observable Behavior:**
- 3 out of 7 struct compile tests passing initially
- Tests using `compileToMultipleClasses()` + `main()` method worked fine
- Tests using `compileWithReturn()` + `evaluate()` method failed with NoClassDefFoundError
- `getGeneratedClasses()` returned empty map when called after `compileWithReturn()`

**Affected Tests:**
- `testFieldAccess` ❌
- `testFieldAccessBoth` ❌
- `testStructInLocalVariable` ❌
- `testMultipleStructTypes` ❌

**Working Tests:**
- `testStructDeclaration` ✅
- `testStructInstantiation` ✅
- `testStructTypeDescriptor` ✅

## Investigation Steps

### 1. Initial Hypothesis: MultiClassLoader Issue
**Tried:** Explicitly loading struct classes before main class
```java
// Tried loading classes in specific order
for (String structClassName : structClasses.keySet()) {
    loader.loadClass(structClassName);
}
Class<?> mainClass = loader.loadClass(className);
```
**Result:** Still failed with same error

### 2. ClassLoader Debug Investigation
**Tried:** Added debug logging to understand class loading
- Confirmed struct classes were being registered in `classDefinitions` map
- Confirmed `MultiClassLoader.findClass()` was being called
- Discovered `findClass()` was calling `super.findClass()` (returning not found)

### 3. Root Cause Discovery
**Key Insight:** Compared working vs failing code paths

**Working path (`compile()`):**
```java
// In generateMainMethod()
rootContext = new CompileContext();  // ✅ Stored in instance field
rootContext.setClassName(className);
```

**Failing path (`compileWithReturn()`):**
```java
// In generateEvaluateMethod()
CompileContext ctx = new CompileContext();  // ❌ Local variable only
ctx.setClassName(className);
```

**The bug:** `getGeneratedClasses()` checks `rootContext`:
```java
public Map<String, byte[]> getGeneratedClasses() {
    if (rootContext != null) {
        return rootContext.getGeneratedClasses();
    }
    return new java.util.HashMap<>();  // Returns empty!
}
```

Since `generateEvaluateMethod()` never set `rootContext`, the method returned an empty map, so no struct classes were registered in the `MultiClassLoader`.

## Root Cause

**Technical Explanation:**

1. `BytecodeGenerator` has instance field `rootContext` used to track generated classes
2. `generateMainMethod()` correctly assigns `rootContext = new CompileContext()`
3. `generateEvaluateMethod()` created a LOCAL variable `CompileContext ctx` instead
4. When `StructDeclarationCompiler` generates struct bytecode, it calls `ctx.addGeneratedClass()`
5. After compilation, tests call `generator.getGeneratedClasses()`
6. This method checks `rootContext`, which is null, so returns empty map
7. Test helper never loads struct classes because map is empty
8. Runtime bytecode references `Point` class, JVM can't find it → NoClassDefFoundError

**Why it worked for some tests:**
- Tests using `compileToMultipleClasses()` call `compile()` which uses `generateMainMethod()`
- `generateMainMethod()` properly sets `rootContext`
- Those tests got the struct classes and loaded them successfully

## Solution

### Fix: Set rootContext in generateEvaluateMethod

**File:** `core/src/main/java/com/elminster/jcp/compile/BytecodeGenerator.java`

**Before (buggy):**
```java
private void generateEvaluateMethod(Block program, Expression expression, DataType returnType) {
    String descriptor = "()" + TypeMapper.toDescriptor(returnType);
    MethodVisitor mv = classWriter.visitMethod(
            ACC_PUBLIC | ACC_STATIC,
            "evaluate",
            descriptor,
            null,
            null
    );
    mv.visitCode();

    // Create compilation context
    CompileContext ctx = new CompileContext();  // ❌ Local only
    ctx.setClassName(className);
    ctx.setNextLocalIndex(0);

    // Use visitor pattern for compilation
    CompileVisitor visitor = new CompileVisitor(mv, ctx);
    // ... rest of method
}
```

**After (fixed):**
```java
private void generateEvaluateMethod(Block program, Expression expression, DataType returnType) {
    String descriptor = "()" + TypeMapper.toDescriptor(returnType);
    MethodVisitor mv = classWriter.visitMethod(
            ACC_PUBLIC | ACC_STATIC,
            "evaluate",
            descriptor,
            null,
            null
    );
    mv.visitCode();

    // Create compilation context and store as rootContext
    // This ensures generated classes (like structs) are tracked
    rootContext = new CompileContext();  // ✅ Stored in instance field
    rootContext.setClassName(className);
    rootContext.setNextLocalIndex(0);

    // Use visitor pattern for compilation
    CompileVisitor visitor = new CompileVisitor(mv, rootContext);  // ✅ Use rootContext
    // ... rest of method
}
```

## Prevention

### 1. Code Pattern Consistency

**Rule:** When `BytecodeGenerator` has multiple code generation methods, ensure they follow the same pattern for context management.

**Pattern to follow:**
```java
// ALWAYS store context in rootContext instance field
rootContext = new CompileContext();
rootContext.setClassName(className);

// ALWAYS pass rootContext to visitor
CompileVisitor visitor = new CompileVisitor(mv, rootContext);
```

### 2. Add Documentation Comment

Added to `BytecodeGenerator.java`:
```java
/**
 * Root compilation context.
 * IMPORTANT: Both generateMainMethod() and generateEvaluateMethod() must
 * assign their context to rootContext so that getGeneratedClasses() can
 * return struct classes and other generated classes.
 */
private CompileContext rootContext;
```

### 3. Test Coverage

**Lesson:** Test both code paths when there are multiple compilation entry points.

**Test matrix:**
```
| Entry Point              | Method Generated | Struct Support |
|--------------------------|------------------|----------------|
| compile()                | main()           | ✅ Tested     |
| compileWithReturn()      | evaluate()       | ✅ Tested     |
| compileToMultipleClasses | main()           | ✅ Tested     |
```

### 4. Future Safeguards

If adding new compilation methods in `BytecodeGenerator`:

1. Check if method generates classes (structs, functions, etc.)
2. If yes, ensure `rootContext` is set
3. Add test that calls `getGeneratedClasses()` and verifies non-empty
4. Test with `MultiClassLoader` to ensure classes can be loaded
