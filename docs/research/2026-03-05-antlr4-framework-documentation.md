## 1. Visitor vs Listener Patterns

### Core Difference

The fundamental distinction is **control flow**:

- **Listeners**: Automatic traversal via `ParseTreeWalker` - callbacks invoked by ANTLR
- **Visitors**: Manual traversal - YOU explicitly call `visit()` on children

### When to Use Each

| Pattern | Best For | Reason |
|---------|----------|--------|
| **Listener** | Simple tree walking, logging, validation | Automatic traversal, no recursion management |
| **Visitor** | AST building, expression evaluation, compilers | Fine-grained control, can return values |

**For MiniLang DSL → Use VISITOR pattern** because:
1. Building JCP AST nodes requires returning values up the tree
2. Need control over which subtrees to process (e.g., short-circuit evaluation)
3. Expression evaluators naturally map to visitor pattern

### Listener Implementation

```java
// Generated by ANTLR from grammar
public interface MiniLangListener extends ParseTreeListener {
    void enterFunctionDecl(MiniLangParser.FunctionDeclContext ctx);
    void exitFunctionDecl(MiniLangParser.FunctionDeclContext ctx);
    // ... more methods
}

// Your implementation
public class MiniLangListenerImpl extends MiniLangBaseListener {
    @Override
    public void enterFunctionDecl(MiniLangParser.FunctionDeclContext ctx) {
        System.out.println("Entering function: " + ctx.ID().getText());
    }
}

// Usage
MiniLangLexer lexer = new MiniLangLexer(input);
CommonTokenStream tokens = new CommonTokenStream(lexer);
MiniLangParser parser = new MiniLangParser(tokens);
ParseTree tree = parser.program();

ParseTreeWalker walker = new ParseTreeWalker();
walker.walk(new MiniLangListenerImpl(), tree);
```

### Visitor Implementation

```java
// Generated by ANTLR (-visitor flag in Maven plugin)
public interface MiniLangVisitor<T> extends ParseTreeVisitor<T> {
    T visitFunctionDecl(MiniLangParser.FunctionDeclContext ctx);
    T visitExpression(MiniLangParser.ExpressionContext ctx);
    // ... more methods
}

// Your implementation - returns JCP AST nodes
public class MiniLangToJcpAstVisitor extends MiniLangBaseVisitor<Node> {

    @Override
    public Node visitFunctionDecl(MiniLangParser.FunctionDeclContext ctx) {
        String name = ctx.ID().getText();

        // CRITICAL: Must explicitly visit children
        List<Parameter> params = ctx.paramList().param().stream()
            .map(p -> (Parameter) visit(p))  // Explicit visit call
            .collect(Collectors.toList());

        Block body = (Block) visit(ctx.block());  // Explicit visit call

        return new FunctionDeclNode(name, params, body);
    }

    @Override
    public Node visitExpression(MiniLangParser.ExpressionContext ctx) {
        if (ctx.PLUS() != null) {
            Node left = visit(ctx.expression(0));   // Explicit visit
            Node right = visit(ctx.expression(1));  // Explicit visit
            return new PlusNode(left, right);
        }
        return visitChildren(ctx);  // Default behavior
    }
}

// Usage
MiniLangLexer lexer = new MiniLangLexer(input);
CommonTokenStream tokens = new CommonTokenStream(lexer);
MiniLangParser parser = new MiniLangParser(tokens);
ParseTree tree = parser.program();

MiniLangToJcpAstVisitor visitor = new MiniLangToJcpAstVisitor();
Node jcpAst = visitor.visit(tree);  // Returns JCP AST root
```

### Critical Visitor Mistake

**Forgetting to call `visit()` on children means subtrees are silently skipped!**

```java
// WRONG - children never processed
@Override
public Node visitBlock(BlockContext ctx) {
    return new BlockNode();  // Oops, no statements added!
}

// CORRECT - explicit visits
@Override
public Node visitBlock(BlockContext ctx) {
    BlockNode block = new BlockNode();
    for (StatementContext stmt : ctx.statement()) {
        block.add((Statement) visit(stmt));  // Process each child
    }
    return block;
}
```

### Performance Considerations

**Don't do complex work during parsing** - parser throws exceptions for error recovery. Do heavy work in visitor/listener AFTER parse completes.

## 2. Error Handling and Recovery

### Custom Error Listener

```java
// Custom error collector
public class MiniLangErrorListener extends BaseErrorListener {
    private final List<SyntaxError> errors = new ArrayList<>();

    @Override
    public void syntaxError(Recognizer<?, ?> recognizer,
                           Object offendingSymbol,
                           int line,
                           int charPositionInLine,
                           String msg,
                           RecognitionException e) {
        errors.add(new SyntaxError(line, charPositionInLine, msg));
    }

    public List<SyntaxError> getErrors() {
        return errors;
    }
}

// Usage
MiniLangParser parser = new MiniLangParser(tokens);
parser.removeErrorListeners();  // Remove console output
MiniLangErrorListener errorListener = new MiniLangErrorListener();
parser.addErrorListener(errorListener);

ParseTree tree = parser.program();

if (!errorListener.getErrors().isEmpty()) {
    for (SyntaxError error : errorListener.getErrors()) {
        System.err.println("Line " + error.getLine() + ": " + error.getMessage());
    }
}
```

### Default Error Handling

ANTLR wraps every rule in try-catch-finally:

```java
// Generated code structure
void r() throws RecognitionException {
    try {
        // rule body
    }
    catch (RecognitionException re) {
        _errHandler.reportError(this, re);
        _errHandler.recover(this, re);  // Attempts recovery
    }
    finally {
        exitRule();  // Always executed
    }
}
```

### Custom Exception Handling Per Rule

```antlr
// Override default behavior for specific rule
functionDecl
    : 'func' ID '(' paramList ')' '->' type block
    ;
    catch[RecognitionException e] {
        throw e;  // Don't attempt recovery, propagate up
    }
```

### Semantic Predicates with Error Messages

```antlr
// Custom error message when predicate fails
ints[int max]
    locals [int i=1]
    : INT ( ',' {$i++;} {$i<=$max}?<fail={"exceeded max "+$max}> INT )*
    ;
```

### Channels for Comments and Whitespace

```antlr
// Send to hidden channel (available but not sent to parser)
BLOCK_COMMENT : '/*' .*? '*/' -> channel(HIDDEN) ;
LINE_COMMENT  : '//' ~[\r\n]* -> channel(HIDDEN) ;
WS            : [ \t\r\n\f]+ -> channel(HIDDEN) ;

// Or completely skip (not available at all)
WS : [ \t\r\n\f]+ -> skip ;
```

**For MiniLang**: Use `-> channel(HIDDEN)` to preserve comments for potential IDE features.

## 3. Left-Recursive Grammar Rules for Operator Precedence

### ANTLR 4's Killer Feature

**ANTLR 4 directly supports left recursion** - the natural way to write expression grammars!

```antlr
// Natural, readable syntax (ANTLR 4 handles this!)
expr : expr '*' expr
     | expr '+' expr
     | INT
     ;
```

ANTLR 3 required awkward right-recursive workarounds. ANTLR 4 rewrites this internally.

### Operator Precedence via Rule Order

```antlr
// Higher alternatives = LOWER precedence
// ANTLR 4 uses alternative order to determine precedence
expr : expr ('*' | '/') expr    // Multiplication/Division (higher precedence)
     | expr ('+' | '-') expr    // Addition/Subtraction (lower precedence)
     | INT                      // Primary
     ;
```

**Order matters**: First alternative binds tightest!

### Associativity Control

```antlr
// Default: left associative (due to left recursion)
expr : expr '*' expr    // 2 * 3 * 4 = (2 * 3) * 4

// Explicit right associativity
expr : expr '^'<assoc=right> expr    // 2 ^ 3 ^ 4 = 2 ^ (3 ^ 4)
     | expr '*' expr
     | expr '+' expr
     | INT
     ;
```

### MiniLang Expression Grammar (Recommended)

```antlr
// Based on standard C/Java precedence
expression
    : expression '[' expression ']'                          // Array access
    | expression '.' ID ('(' argumentList? ')')?             // Field/method
    | ('!' | '-') expression                                 // Unary
    | expression ('*' | '/' | '%') expression                // Multiplicative
    | expression ('+' | '-') expression                      // Additive
    | expression ('<' | '<=' | '>' | '>=') expression        // Comparison
    | expression ('==' | '!=') expression                    // Equality
    | expression '&&' expression                             // Logical AND
    | expression '||' expression                             // Logical OR
    | primary                                                // Atoms
    ;

primary
    : INT                                    // Integer literal
    | DOUBLE                                 // Double literal
    | STRING                                 // String literal
    | 'true' | 'false'                       // Boolean literal
    | ID                                     // Variable reference
    | ID '(' argumentList? ')'               // Function call
    | '[' expressionList? ']'                // Array literal
    | ID '(' argumentList? ')'               // Struct instantiation
    | '(' expression ')'                     // Parenthesized
    ;
```

### Internal Rewriting (How ANTLR 4 Works)

```antlr
// Your natural grammar:
expr : expr '*' expr
     | expr '+' expr
     | INT
     ;

// ANTLR 4 rewrites to (conceptually):
expr[int pr] : INT
               ( {4 >= $pr}? '*' expr[5]     // Precedence check
               | {3 >= $pr}? '+' expr[4]
               )*
             ;
```

Semantic predicates ensure correct precedence. **You don't write this - ANTLR generates it!**

### Alternative Labels for Distinct Cases

```antlr
// Use # labels to generate specific visitor methods
expression
    : expression '*' expression    #MultExpr
    | expression '+' expression    #AddExpr
    | INT                          #IntExpr
    ;

// Generates separate visitor methods:
// - visitMultExpr(MultExprContext ctx)
// - visitAddExpr(AddExprContext ctx)
// - visitIntExpr(IntExprContext ctx)
```

**For MiniLang**: Use labels to cleanly map to JCP AST node types!

## 4. Token and Lexer Rule Best Practices

### Naming Convention

```antlr
// Parser rules: lowercase
functionDecl : 'func' ID '(' paramList ')' block ;

// Lexer rules: UPPERCASE
ID : [a-zA-Z_][a-zA-Z0-9_]* ;
INT : [0-9]+ ;

// Fragment rules: helper, don't produce tokens
fragment DIGIT : [0-9] ;
fragment LETTER : [a-zA-Z] ;
```

### Token Ordering (CRITICAL!)

**Lexer matches longest token first, then FIRST rule if tied.**

```antlr
// WRONG - 'if' always matches ID, 'if' keyword never recognized!
ID : [a-zA-Z]+ ;
IF : 'if' ;

// CORRECT - keywords BEFORE identifiers
IF     : 'if' ;
WHILE  : 'while' ;
RETURN : 'return' ;
ID     : [a-zA-Z_][a-zA-Z0-9_]* ;
```

**For MiniLang**: Place ALL keywords before ID rule.

### Fragment Rules

```antlr
// Fragments are reusable building blocks, not tokens
INT : DIGIT+ ;
DOUBLE : DIGIT+ '.' DIGIT* EXPONENT?
       | DIGIT+ EXPONENT
       ;

fragment DIGIT : [0-9] ;
fragment EXPONENT : [eE] [+-]? DIGIT+ ;
```

### String Literals with Escapes

```antlr
// Standard string handling
STRING : '"' (ESC | ~["\\])* '"' ;

fragment ESC : '\\' [tnr"\\] ;  // \t \n \r \" \\
```

### Comments and Whitespace

```antlr
// Line comments
LINE_COMMENT : '#' ~[\r\n]* -> channel(HIDDEN) ;

// Block comments (if added later)
BLOCK_COMMENT : '/*' .*? '*/' -> channel(HIDDEN) ;

// Whitespace
WS : [ \t\r\n\f]+ -> channel(HIDDEN) ;
```

**Channel vs Skip:**
- `-> channel(HIDDEN)`: Token exists but not sent to parser (can retrieve later)
- `-> skip`: Token discarded entirely (more efficient)

**For MiniLang**: Use `channel(HIDDEN)` for potential IDE/tooling support.

### Common Pitfall: String Ambiguity

```antlr
// WRONG - ambiguous, parser can't use literals
QUOTE : '"' ;
STRING_CONTENT : ~["]+ ;

// CORRECT - single unambiguous rule
STRING : '"' ~["]* '"' ;
```

### Lexer Modes (For Complex Syntax)

```antlr
// Example: XML-like tags with different lexing inside vs outside
DEFAULT_MODE;
OPEN_TAG : '<' -> pushMode(INSIDE_TAG) ;
TEXT : ~[<]+ ;

mode INSIDE_TAG;
CLOSE_TAG : '>' -> popMode ;
TAG_NAME : [a-zA-Z]+ ;
```

**For MiniLang**: Not needed - simple uniform syntax.

### Scientific Notation

```antlr
// Comprehensive number handling
DOUBLE
    : DIGIT+ '.' DIGIT* EXPONENT?    // 3.14, 3.14e10
    | DIGIT+ EXPONENT                // 3e10
    | '.' DIGIT+ EXPONENT?           // .14, .14e10
    ;

INT : DIGIT+ ;

fragment DIGIT : [0-9] ;
fragment EXPONENT : [eE] [+-]? DIGIT+ ;
```

## 7. Source Location Tracking from Tokens

### Token Attributes

Every token and parse tree node provides location information:

```java
Token token = ctx.ID().getSymbol();

// Line number (1-indexed)
int line = token.getLine();

// Column position (0-indexed)
int column = token.getCharPositionInLine();

// Token text
String text = token.getText();

// Start/stop indices in character stream
int start = token.getStartIndex();
int stop = token.getStopIndex();

// Token type
int type = token.getType();
```

### Accessing in Grammar Actions

```antlr
functionDecl
    : 'func' name=ID '(' paramList ')' '->' returnType block
      {
          Token funcToken = $name;
          System.out.println("Function " + funcToken.getText() +
                           " at line " + funcToken.getLine());
      }
    ;
```

### In Visitor Methods

```java
@Override
public Node visitFunctionDecl(FunctionDeclContext ctx) {
    Token nameToken = ctx.ID().getSymbol();

    String name = nameToken.getText();
    int line = nameToken.getLine();
    int column = nameToken.getCharPositionInLine();

    // Create JCP node with source location
    FunctionDeclNode node = new FunctionDeclNode(name);
    node.setSourceLocation(line, column);  // Track for error reporting

    return node;
}
```

### ParserRuleContext Source Spans

```java
// Get source location for entire rule match
@Override
public Node visitExpression(ExpressionContext ctx) {
    // Start token of the entire expression
    Token start = ctx.getStart();

    // Stop token of the entire expression
    Token stop = ctx.getStop();

    // Span: [start.getStartIndex(), stop.getStopIndex()]
    int startLine = start.getLine();
    int endLine = stop.getLine();

    // Extract original source text for this rule
    String sourceText = ctx.getText();  // Concatenated token text

    return buildNode(ctx, startLine, endLine);
}
```

### Getting Original Source Text

```java
// Preferred: Use TokenStream to preserve whitespace
TokenStream tokens = parser.getTokenStream();
String text = tokens.getText(ctx.getSourceInterval());

// Alternative: From context directly (strips whitespace)
String text = ctx.getText();
```

### Multiple Token References with Labels

```antlr
// Use labels to distinguish multiple tokens of same type
decl : type id=ID ';'
       {
           System.out.println("Variable " + $id.text +
                            " at line " + $id.line);
       }
     | t=ID id=ID ';'  // Type alias case
       {
           System.out.println("Type: " + $t.text +
                            ", Var: " + $id.text);
       }
     ;
```

### Common Attributes

| Attribute | Description | Example |
|-----------|-------------|---------|
| `$TOKEN.text` | Token text | `$ID.text` → `"myVar"` |
| `$TOKEN.line` | Line number (1-indexed) | `$ID.line` → `42` |
| `$TOKEN.pos` | Column (0-indexed) | `$ID.pos` → `8` |
| `$TOKEN.index` | Token index in stream | `$ID.index` → `156` |
| `$TOKEN.type` | Token type constant | `$ID.type` → `MiniLangParser.ID` |
| `$start` | First token of current rule | `$start.line` |
| `$stop` | Last token of current rule | `$stop.line` |

### Error Reporting with Location

```java
public class MiniLangAstBuilder extends MiniLangBaseVisitor<Node> {

    @Override
    public Node visitAssignment(AssignmentContext ctx) {
        Token varToken = ctx.ID().getSymbol();
        Node value = visit(ctx.expression());

        // Type checking
        if (!isCompatible(varToken.getText(), value.getType())) {
            throw new SemanticException(
                String.format("Type mismatch at %s:%d:%d - cannot assign %s to %s",
                    ctx.getStart().getInputStream().getSourceName(),
                    varToken.getLine(),
                    varToken.getCharPositionInLine(),
                    value.getType(),
                    getVariableType(varToken.getText())
                )
            );
        }

        return new AssignmentNode(varToken.getText(), value);
    }
}
```

### Tracking Source Locations in JCP AST Nodes

```java
// Extend JCP nodes with source location
public abstract class JcpNode implements Node {
    private SourceLocation location;

    public void setSourceLocation(int line, int column) {
        this.location = new SourceLocation(line, column);
    }

    public SourceLocation getSourceLocation() {
        return location;
    }
}

// Usage in visitor
@Override
public Node visitFunctionCall(FunctionCallContext ctx) {
    Token funcToken = ctx.ID().getSymbol();

    FunctionCallNode node = new FunctionCallNode(funcToken.getText());
    node.setSourceLocation(
        funcToken.getLine(),
        funcToken.getCharPositionInLine()
    );

    // For debugger breakpoints
    node.setSourceFile(ctx.getStart().getInputStream().getSourceName());

    return node;
}
```

## 8. Real-World Grammar Examples

### Calculator Grammar (Expression Precedence)

From `antlr/grammars-v4`:

```antlr
grammar calculator;

// Top-level: equations with relational operators
equation
    : expression relop expression
    | expression
    ;

relop
    : EQ | GT | LT
    ;

// Addition/subtraction (lowest precedence for arithmetic)
expression
    : multiplyingExpression ((PLUS | MINUS) multiplyingExpression)*
    ;

// Multiplication/division
multiplyingExpression
    : powExpression ((TIMES | DIV) powExpression)*
    ;

// Exponentiation (right-associative via recursion structure)
powExpression
    : signedAtom (POW signedAtom)*
    ;

// Unary operators
signedAtom
    : PLUS signedAtom
    | MINUS signedAtom
    | func_
    | atom
    ;

// Terminals
atom
    : scientific
    | variable
    | constant
    | LPAREN expression RPAREN
    ;

func_
    : funcname LPAREN expression (COMMA expression)* RPAREN
    ;

funcname
    : COS | SIN | TAN | ACOS | ASIN | ATAN
    | LN | LOG | SQRT
    ;

constant
    : PI | EULER | I
    ;

scientific
    : SCIENTIFIC_NUMBER
    | number
    ;

variable
    : VARIABLE
    ;

number
    : NUMBER
    ;

// Lexer rules
COS   : 'cos' ;
SIN   : 'sin' ;
TAN   : 'tan' ;
// ... more functions

LPAREN : '(' ;
RPAREN : ')' ;
PLUS   : '+' ;
MINUS  : '-' ;
TIMES  : '*' ;
DIV    : '/' ;
POW    : '^' ;
// ... more operators

SCIENTIFIC_NUMBER
    : NUMBER (E SIGN? NUMBER)?
    ;

NUMBER
    : DIGIT+ ('.' DIGIT+)?
    ;

VARIABLE
    : LETTER (LETTER | DIGIT)*
    ;

fragment DIGIT  : [0-9] ;
fragment LETTER : [a-zA-Z] ;
fragment E      : [eE] ;
fragment SIGN   : [+-] ;

WS : [ \t\r\n]+ -> skip ;
```

**Key Lessons:**
1. Precedence via nesting depth (not alternative order for non-left-recursive)
2. Right-associativity via recursion structure (not `<assoc=right>`)
3. Clear separation: terminals → atoms → operators

### Comparing Approaches

**Left-recursive (ANTLR 4 modern):**
```antlr
expr : expr '*' expr    #MultExpr
     | expr '+' expr    #AddExpr
     | INT              #IntExpr
     ;
```

**Non-left-recursive (traditional, still valid):**
```antlr
expr : term ((PLUS | MINUS) term)* ;
term : factor ((TIMES | DIV) factor)* ;
factor : INT | LPAREN expr RPAREN ;
```

**For MiniLang**: Use left-recursive with labels for cleaner visitor methods.

## 9. Complete MiniLang Grammar Template

### Recommended Structure

```antlr
grammar MiniLang;

@header {
package com.elminster.minilang.parser;
}

// ========== PARSER RULES ==========

program
    : statement* EOF
    ;

statement
    : variableDecl
    | assignment
    | functionDecl
    | structDecl
    | ifStatement
    | whileStatement
    | returnStatement
    | breakStatement
    | continueStatement
    | expressionStatement
    ;

variableDecl
    : 'let' ID ':' type '=' expression NEWLINE
    ;

assignment
    : ID '=' expression NEWLINE
    ;

functionDecl
    : 'func' ID '(' parameterList? ')' '->' type block
    ;

structDecl
    : 'struct' ID '{' fieldList '}'
    ;

ifStatement
    : 'if' expression block ('else' block)?
    ;

whileStatement
    : 'while' expression block
    ;

returnStatement
    : 'return' expression? NEWLINE
    ;

breakStatement
    : 'break' NEWLINE
    ;

continueStatement
    : 'continue' NEWLINE
    ;

expressionStatement
    : expression NEWLINE
    ;

block
    : '{' statement* '}'
    ;

// Expression with standard precedence
expression
    : expression '[' expression ']'                      #ArrayAccess
    | expression '.' ID                                  #FieldAccess
    | expression '.' ID '(' argumentList? ')'            #MethodCall
    | ('!' | '-') expression                             #UnaryExpr
    | expression ('*' | '/' | '%') expression            #MultExpr
    | expression ('+' | '-') expression                  #AddExpr
    | expression ('<' | '<=' | '>' | '>=') expression    #CompareExpr
    | expression ('==' | '!=') expression                #EqualityExpr
    | expression '&&' expression                         #LogicalAndExpr
    | expression '||' expression                         #LogicalOrExpr
    | primary                                            #PrimaryExpr
    ;

primary
    : INT                                   #IntLiteral
    | DOUBLE                                #DoubleLiteral
    | STRING                                #StringLiteral
    | 'true'                                #TrueLiteral
    | 'false'                               #FalseLiteral
    | ID                                    #Identifier
    | ID '(' argumentList? ')'              #FunctionCall
    | '[' expressionList? ']'               #ArrayLiteral
    | ID '(' argumentList? ')'              #StructInstantiation
    | '(' expression ')'                    #ParenExpr
    ;

// Helper rules
parameterList
    : parameter (',' parameter)*
    ;

parameter
    : ID ':' type
    ;

argumentList
    : expression (',' expression)*
    ;

expressionList
    : expression (',' expression)*
    ;

fieldList
    : field (',' field)*
    ;

field
    : ID ':' type
    ;

type
    : 'int'
    | 'double'
    | 'boolean'
    | 'string'
    | 'void'
    | type '[' ']'              // Array types
    | ID                        // Struct types
    ;

// ========== LEXER RULES ==========

// Keywords (MUST come before ID)
LET      : 'let' ;
FUNC     : 'func' ;
STRUCT   : 'struct' ;
IF       : 'if' ;
ELSE     : 'else' ;
WHILE    : 'while' ;
RETURN   : 'return' ;
BREAK    : 'break' ;
CONTINUE : 'continue' ;
TRUE     : 'true' ;
FALSE    : 'false' ;

// Literals
DOUBLE
    : DIGIT+ '.' DIGIT* EXPONENT?
    | DIGIT+ EXPONENT
    | '.' DIGIT+ EXPONENT?
    ;

INT
    : DIGIT+
    ;

STRING
    : '"' (ESC | ~["\\])* '"'
    ;

// Identifiers (after keywords!)
ID
    : [a-zA-Z_][a-zA-Z0-9_]*
    ;

// Operators
PLUS   : '+' ;
MINUS  : '-' ;
STAR   : '*' ;
SLASH  : '/' ;
PERCENT: '%' ;
EQ     : '==' ;
NE     : '!=' ;
LT     : '<' ;
LE     : '<=' ;
GT     : '>' ;
GE     : '>=' ;
AND    : '&&' ;
OR     : '||' ;
NOT    : '!' ;
ASSIGN : '=' ;
ARROW  : '->' ;

// Delimiters
LPAREN : '(' ;
RPAREN : ')' ;
LBRACE : '{' ;
RBRACE : '}' ;
LBRACK : '[' ;
RBRACK : ']' ;
COMMA  : ',' ;
DOT    : '.' ;
COLON  : ':' ;
SEMI   : ';' ;

// Newline (statement terminator)
NEWLINE
    : '\r'? '\n'
    | '\r'
    ;

// Comments and whitespace
LINE_COMMENT
    : '#' ~[\r\n]* -> channel(HIDDEN)
    ;

WS
    : [ \t]+ -> channel(HIDDEN)
    ;

// Fragments
fragment DIGIT : [0-9] ;
fragment EXPONENT : [eE] [+-]? DIGIT+ ;
fragment ESC : '\\' [tnr"\\] ;
```

## 10. Best Practices Summary

### Grammar Design

1. **Use left-recursion for expressions** - natural and readable
2. **Label alternatives** with `#` for clean visitor methods
3. **Keywords before ID** in lexer rules (ordering matters!)
4. **Fragment rules** for reusable lexer patterns
5. **EOF in start rule** to ensure complete input parsing

### Error Handling

1. **Custom error listeners** for collecting syntax errors
2. **channel(HIDDEN) for comments** to preserve for IDE support
3. **Semantic predicates** for custom validation with error messages
4. **Source location tracking** in every AST node for error reporting

### Visitor Pattern

1. **Choose visitor for AST building** (return values needed)
2. **Explicit visit() calls** on all children (critical!)
3. **Map grammar labels to AST node types** for clarity
4. **Track source locations** as you build AST nodes

### Maven Integration

1. **Place grammars in `src/main/antlr4/`** matching package structure
2. **Enable `-visitor` flag** in plugin configuration
3. **Use latest ANTLR 4.13.1** for Java 11+ compatibility
4. **Generated sources auto-added** to compile path

### Testing

1. **Use grun for interactive testing** during development
2. **Write parser tests** with valid and invalid inputs
3. **Test error recovery** to ensure good error messages
4. **Test visitor on real programs** before full integration
